## 1. 项目背景

燕山大学西校区（河北秦皇岛，约 2.0 km × 1.5 km）需要规划一套校内给水管道铺设方案。核心是：

- 把校园里 **45 个供水建筑**连成一张管网；
- 管道**必须沿现有道路铺设**（不能穿楼、不能穿草坪直线拉过去）；
- 用**最小生成树**求最省的管网骨架，用 **Dijkstra** 求沿路网的真实距离，用**树形 DP** 从末端向根部累加需求来定管径；
- 最后做一张**可交互的 2.5D 页面**，能自定义起点终点、能看动画、能对比方案。

已经完成的部分：**数据采集、坐标校准、建筑注册表、算法原型、2.5D 静态图**。
你要做的是：**把它们变成一个正式的可交互系统**。

## 3. 核心功能需求

### 3.1 三档规划模式（最重要）

页面必须支持三种工作模式，**系统要自动判别**。这是整个项目被提问最多的地方，写之前先把这一节读完。

#### 3.1.0 判别优先级（唯一权威规则）

模式不是用户点按钮选的，而是**由"起点是否被指定" + "终点集合是否为空"两个状态推出来的**：

```
hasSource = 用户显式指定了水源（点图 / 下拉选 / 手动输坐标），且未被重置
T = 用户显式选中的供水目标集合

if T 为空:                     mode = 'C'   # 什么都不给 → 全校方案（45 个全连）
elif hasSource:                mode = 'A'   # 起点 + 终点都有 → 单源定向路由
else:                          mode = 'B'   # 只给终点 → 自动选最优起点
```

注意两处容易写错的地方：

1. **"默认水源"不算 `hasSource`**。初始态用的是 `meta.source` 那个假设接入点，但那只是 C 模式的默认根，**不能**因为"反正有个默认起点"就把状态判成 A。否则页面一打开就永远是 A 模式，B 模式永远触发不了。
2. **终点为空 ≠ 用户没操作**。用户把选中的楼全部取消勾选，状态回到 C，要显式提示"已清空终点，回到全校方案"，而不是报错。

状态条文案模板（固定格式，方便自动化断言）：

```
模式 C ｜ 未指定起点与终点，执行全校方案（45 个目标，共 220 段管道）
模式 B ｜ 已选 3 个终点，未指定起点 → 自动选择「西校区7号门」（候选 3 个，成本最低）
模式 A ｜ 起点「西校区6号门」→ 4 个终点，沿路网定向路由
```

#### 3.1.1 模式 A：用户指定了起点和终点

**触发条件**：`hasSource == True` 且 `|T| >= 1`。

**输入**：起点（水源，可以是校门候选、图上任意点、或手动坐标）+ 终点集合 T。

**算法**：

1. 起点归一化：若起点是经纬度，先用 `insert_target` 投影到最近路段，得到图节点 `s`（投影距离 > 250 m 直接判失败，见 §5）。
2. 对 `s` 跑一次 Dijkstra，得 `dist[] / prev[]`。
3. 若 `|T| == 1`：直接取 `dist[t]` 和 `path_edges(prev, t)`，输出单条管线路由。
4. 若 `|T| >= 2`：以 `{s} ∪ T` 为点集跑 **Kruskal MST**（两两距离全部来自这一次 Dijkstra 的 `dist`，不需要跑多源 Dijkstra，因为树只以 s 为根）。
5. 在得到的树上做树形 DP 定管径（§3.5.4），得到每段的 `flow / q_ls / dn / order`。

**复杂度**：`O((V+E) log V)` 建距离 + `O(N² log N²)` 排序，`N = |T|+1 ≤ 46`。所以模式 A 是**最快**的一档，可以做到每次点击 100 ms 内出结果。

**用户看到的反馈**（缺一不可）：

- 地图上高亮那条管道路径，其他管道变灰；
- 路径上一段一段能悬停看 `DN / 长度 / 流量 / 层级`；
- 顶部给出三个数：**沿路网总长**（`Σ dist` 或 MST 权）、**管道实长**、**造价估算**；
- 右上角显示"起点投影距离 X m"——如果 > 30 m 要标黄，提示"该点不在路上，已就近投影"；
- 给 2~3 条备选（加分项）：最短距离 / 加权最短路（走主路、少走小路）/ 绕开 `steps` 的路径，列表对比总长与造价。**如果只做一条，就不要在 UI 上出现"备选"按钮**，避免点了没反应。

**验收命令**：
```powershell

python -m src.plan --source-gate 6 --targets X01
```

**算法**：

```
best = None
for each s in SOURCE_CANDIDATES:
    nids = insert_target(s)                 # 投影到最近路段，得到图节点
    D    = dijkstra(nids)                   # 一次 Dijkstra，得到 s 到所有节点的距离
    cost = MST_cost([nids] + T_nids, D)     # 以 D 为权重跑 Kruskal，返回总权
    star = sum(D[t] for t in T_nids)        # 顺带算星形对照
    table.append((s.id, s.name, cost, star, D))
best = argmin(cost)
```

#### 3.1.3 模式 C：什么都不给

**触发条件**：`|T| == 0`（终点集合为空，无论 `hasSource` 是什么）。

**算法**：

- 根固定为 `meta.source` 投影后的节点（= `source_node`，nid 961 所在的位置，接路 7 号门，距离 0.00 m）；
- 对全部 45 个供水目标跑 Kruskal MST；
- 在树上做树形 DP 定管径。

**这一档的结果数据里已经算好了**：`pipes`（220 段）、`tree_edges`（45 条）、`stats` 全套。所以模式 C 的正确实现不是"现场重算"，而是**先读现成结果直接渲染，同时允许"重算"按钮现场跑一遍做对拍**。两者结果必须一致——这是最省力的验证手段。

**用户看到的反馈**：

1. 完整管网 + 全套统计面板（14 行，见 §4）；
2. 方案对比（**注意口径，四个数不是同一件事**）：沿路网 MST **8115.9 m**、实际管长 **7237.2 m**、直线 MST **5632.2 m**、星形 **40960.8 m**。可以说"沿路网比直线多走 **27.0%**"（`1−5632.2/8115.9`）和"实际管长比星形省 **82.3%**"（`1−7237.2/40960.8`），并解释"为什么不用直线"；
3. 水源位置必须标"**假设**"，并注明"如需另选起点请点选校门 → 自动切换到模式 B/A"。

### 3.5 算法规范

#### 3.5.1 路网图构造

- **数据来源**：`bundle.roads`，**153 条 way**（148 条 OSM + 5 条手描广场环路）。已剔除 `highway=steps`（8 条）与 `construction`（1 条），不要再自己筛一遍。
- **规模**：153 条 way 展开后按坐标去重、再插入 45 个目标点 + 1 个水源点，最终是 **1,035 节点 / 1,151 边**。对不上就说明建图写错了。
- **节点**：所有道路折点，用 `(round(lat,7), round(lon,7))` 做全局去重。**这是本项目最容易踩的坑**：如果按每条 way 的局部坐标建节点，共享顶点会被拆成两个节点，图会碎成几十块，最后只有 7 个目标可达、主分量只剩 8 个节点。必须用一个全局字典 `coord_reg[(round(lat,7), round(lon,7))] = nid`。
- **边权**：`w = 真实长度(m) × 道路类型系数`。

  类型系数表（**用这一张，别自己估**）：

  | highway | 系数 | 含义 |
  |---|---|---|
  | `unclassified` | **1.00** | 校内普通支路，基准 |
  | `tertiary` / `secondary` | **1.15** | 市政主路：开口、破路、恢复成本高 |
  | `residential` / `service` | **1.30** | 小区/服务道路，施工协调难 |
  | `cycleway` / `footway` / `path` | **1.60** | 步行/自行车道，埋管受限 |
  | `trunk` | 1.00 | 校区内只有 2 条，无差别处理 |
  | `steps` / `construction` | 排除 | 台阶不能埋管；在建道路不稳定 |

  > ⚠️ **口径差异，必须知情**：`06_代码/build_bundle_v2.py` 里现行常量是 `HW_ALLOW = {'trunk':1.0,'secondary':1.0,'tertiary':1.0,'residential':1.0,'unclassified':1.0,'service':1.15,'cycleway':1.3,'footway':1.3,'path':1.6}`——**主路与小区路按 1.00 计，只有 service/cycleway/footway/path 加权**。本提示词采用上面那张"物理含义"表作为**规范值**。二者不可混用：如果你要复现 `stats.mst_length_m = 8115.9`，**必须**用代码里的 `HW_ALLOW`；如果按上面的规范表算，MST 总长会不同（主路会被加权）。**建议做法**：默认用代码里那张（保证能对上 8115.9），把规范表作为"可调参数"暴露给用户，在报告里说明两者的差别与理由。这条必须写进你的 README，别让评委抓到这个不一致。

- **建筑接入（`insert_target`）**：把建筑质心投影到最近路段：

  ```
  (d, eid, t, qx, qy) = 遍历所有边，求点到线段最近点   # 线性扫描 O(E)
  if d > 250.0:                    return (None, d)      # 太远，判该目标不可达
  if t < 1e-4:                     return (e.a, d)       # 端点复用，★不改图
  if t > 1-1e-4:                   return (e.b, d)       # 端点复用，★不改图
  # 只有真正落在边中间才分裂：
  edges.pop(eid); adj[e.a].remove(eid); adj[e.b].remove(eid)
  nid = add_node(lonlat(qx, qy))
  add_edge(e.a, nid, hypot(q - a) × 系数, e.hw)
  add_edge(nid, e.b, hypot(b - q) × 系数, e.hw)
  ```

  > ⚠️ **第二个致命坑**：端点分支**必须直接 return，不许改动图**。曾经因为"无论是否分裂都执行 `edges.pop(eid)`"，图被反复破坏，最后出现 `UNREACH 29`、连通分量只剩 8 个节点。修法就是上面这三行 early return。

- **连通性预检**：建图后先跑一次 BFS 求连通分量。原始纯 OSM+手描路网是 `components 2, sizes [927, 34]`（那 34 个节点是一条与主网不连的断头小路）。**接入任何外部点之前，必须先从最大连通分量里找最近顶点**，否则可能接到那条死路上。接完 5 条手描支路后主分量应包含全部 45 个目标，`UNREACH` 必须为 **0**。

#### 3.5.2 Dijkstra（求真实距离）

```python
def dijkstra(adj, edges, s):
    """返回 (dist, prev)；prev[v] = 到达 v 的【边 id】，不是前驱节点 id。"""
    dist = {n: inf for n in adj}; dist[s] = 0.0
    prev = {}
    heap = [(0.0, s)]                      # heapq 二叉堆
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u] + 1e-12: continue   # 惰性删除，跳过过期项
        for eid in adj[u]:
            e = edges[eid]
            v = e['b'] if e['a'] == u else e['a']
            nd = d + e['w']
            if nd < dist[v] - 1e-12:       # 严格小于才松弛，带 eps 防浮点抖动
                dist[v] = nd; prev[v] = eid
                heapq.heappush(heap, (nd, v))
    return dist, prev


def path_edges(prev, target):
    """从 prev 回溯出 target 到根的边序列。"""
    out, t = [], target
    while t is not None and t in prev:
        eid = prev[t]
        out.append(eid)
        e = edges[eid]
        t = e['a'] if e['b'] == t else e['a']
    return out
```

- 复杂度：`O((V+E) log V)`，二叉堆实现。
- 本规模（1035 节点 / 1151 边）**单次 20 ms 量级**；45 个目标各跑一次 ≈ 1 s（提交时一次性算完存 JSON，不要每次渲染重跑）。
- 前端若要在浏览器里实时重算：用"按距离排序的数组 + 二分插入"当优先队列就够（实测单次 2 ms），不需要手写堆。

#### 3.5.3 Kruskal（求管网骨架）

```python
def kruskal(nodes, dist):
    """nodes = [源点] + [各目标节点]；dist 是 Dijkstra 得到的全源距离表。"""
    pairs = [(dist[a][b], a, b) for i, a in enumerate(nodes)
                              for b in nodes[i+1:] if dist[a][b] < inf]
    pairs.sort()                                    # O(E log E)
    par = {n: n for n in nodes}
    def find(x):                                    # 路径压缩
        while par[x] != x:
            par[x] = par[par[x]]; x = par[x]
        return x
    mst, total = [], 0.0
    for w, a, b in pairs:
        ra, rb = find(a), find(b)
        if ra != rb:                                # 不成环才加入
            par[ra] = rb; mst.append((a, b, w)); total += w
            if len(mst) == len(nodes) - 1: break
    if len(mst) != len(nodes) - 1:
        raise RuntimeError('MST incomplete %d/%d' % (len(mst), len(nodes)-1))
    return mst, total
```

- 复杂度：`O(E log E)`，`E = C(45,2) = 990`（不含源点）或 `C(46,2) = 1035`（含源点）。
- **为什么是 MST 而不是最短路径**：我们要的是一张"把所有楼都连起来"的网，不是"从 A 到 B 的最短路"。MST 保证连通且总长最小。更严格的论证见 `03_实施方案/实施方案_算法设计.md` 的交换论证：MST 同时是下界与可行解，因此最优。
- **诚实交代边界**：这个最优性依赖四条假设——单水源、不考虑管径、不考虑容量、需求点已在路网节点上。管径分级（§3.5.4）是在 MST 之上的**第二级**优化，不改变拓扑；如果再叠加容量约束或允许分流，MST 就不再严格最优。报告里要写清楚。

#### 3.5.4 树形 DP（自底向上定管径）

在 MST 上以水源为根。**注意这一步的真实语义，比教科书写法多两个坑**：

```python
# ---- 1. 定父与深度（BFS）----
depth = {src: 0}; par = {src: None}; order = [src]
qi = 0
while qi < len(order):
    u = order[qi]; qi += 1
    for v, w in tree[u]:
        if v not in depth:
            depth[v] = depth[u] + 1; par[v] = u; order.append(v)

# ---- 2. 子树需求自底向上累加 ----
sub = {n: demand.get(n, 0.0) for n in alln}   # ★ 只有供水目标有 demand，其余节点 0
for u in reversed(order):                      # reversed(order) 就是拓扑逆序
    p = par.get(u)
    if p is not None:
        sub[p] += sub[u]

# ---- 3. 定每段流量：★不是 sub[child]，是"路径并集 + 沿路叠加"----
eid_flow, eid_order = {}, {}
for u in order:
    p = par.get(u)
    if p is None: continue
    for eid in path_edges(prev_of_p, u):       # 沿路网从 p 到 u 的每一条边都要计
        eid_flow[eid] = eid_flow.get(eid, 0.0) + sub[u]
        eid_order[eid] = min(eid_order.get(eid, 999), depth[u])
```

> ⚠️ **第三个坑（最关键）**：`pipes` **不是** MST 的那 45 条树边，而是"树边对应路网路径的并集"，共 **220 段**。
> 因为两个目标之间的最短路可能很长、会经过许多路网边，这些边全都要铺管；如果多条路径共用了同一段路，流量要**叠加**（不是取最大）。这解释了为什么 `pipe_length_m (7237.2) < mst_length_m (8115.9)`——后者是在**加权**边权下的 MST 权（主路被加权抬高），前者是**真实米数**下的路径并集长度。两个数不一样是正常的，不要试图让它们相等。
> `order` 的语义：该段边上"最靠根的那个目标子树"的深度，用来驱动生长动画的顺序。

**定管径**：

```python
def pick_dn(q_ls, v_econ=1.0):
    # 面积 A = Q/v，直径 d = √(4A/π)，单位换算到 mm
    d_mm = math.sqrt(4 * (q_ls / 1000.0) / (math.pi * v_econ)) * 1000.0
    for dn in DN_LIST:            # DN_LIST 已升序
        if dn >= d_mm: return dn
    return DN_LIST[-1]            # 超出 DN500 就取 DN500，并在页面标红警示

DN_LIST = [32, 40, 50, 65, 80, 100, 125, 150, 200, 250, 300, 350, 400, 500]
```

其中 `q_ls = flow / (PEAK_HOURS * 3600)`，`PEAK_HOURS = 24/Kh = 9.6`，`flow` 单位是 L/d。

- 复杂度：`O(V + E_path)`，线性。
- **本方案实际只用到 13 档管径，没有 DN350**。`dn_len` 分布见 §2.1。
- 最粗 DN500 出现在水源出口段（`q_ls = 199.29`）。

#### 3.5.5 用水量与设计流量

```
d_i   = floor_area_i × 用水指标_cat(i)          # L/d
D     = Σ d_i                                  # 6887403.3 L/d = 6887.4 m³/d
Q_max = D × Kh / (24 × 3600)                   # L/s = 199.29 L/s
```

> `Kh` 乘在**日总量**上，等价于"全部日用水集中在 24/Kh = 9.6 小时内均匀用完"。不要再乘一次，也不要把它拆成小时系数。常见错误是写成 `Σd/24×Kh/3600` 与 `Σd×Kh/86400` 两个公式都乘了 Kh——它们其实恒等，但有人会写第三个式子再乘一遍。

#### 3.5.6 造价估算

```
总造价 = Σ (各段真实长度 × 该段管径对应单价)
```

球墨铸铁给水管综合单价（含管材 / 管件 / 土方 / 回填 / 路面恢复，元/m）：

| DN | 32 | 40 | 50 | 65 | 80 | 100 | 125 | 150 | 200 | 250 | 300 | 350 | 400 | 500 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 元/m | 140 | 160 | 185 | 225 | 270 | 330 | 400 | 480 | 620 | 800 | 1000 | 1200 | 1450 | 1900 |

- 复现目标：**4682809 元**（468.3 万元）。这个数是"量级估算"，不是施工图预算，报告里必须这么说。
- 注意各段长度用 `pipes[].length`（真实米），**不要**用带类型系数的 `w`，否则造价会虚高。

## 5. 数据边界与禁止假设

**这一章是全文档最重要的部分。** 这个项目的难点不在算法，在数据。下面每一条都是真实踩过的坑，**你要是凭"看起来合理"去补，就会把这个项目做废**。

### 5.1 建筑的三种几何来源，强度完全不同

`buildings[].src` 只有两个取值，但实际有三种可信度：

| 来源 | 数量 | 判据 | 强度 | 页面上必须怎么说 |
|---|---|---|---|---|
| OSM 实测轮廓 | **50** | `src == "OSM"` | 强：多边形实测 | 可正常绘制、正常标注 |
| 影像 bbox 代理 | **11** | `src == "measured"` | 中：只有外接矩形，不是轮廓 | 虚线描边，tooltip 注明"轮廓为影像量测的矩形代理，非实测轮廓" |
| 无几何，只有楼名 | **10 组（Y01–Y11）** | 不在 `buildings[]` 里 | 无 | 只在"待定位清单"里列名，**不上图、不入计算** |

**11 个 bbox 代理是哪些**：`src == "measured"` 的 11 条。它们的 footprint 是由 `measured.bbox = [x0, y0, x1, y1]` 四个角点拼出来的矩形（米制局部坐标），面积直接取 `measured.area_m2`，**不是**矩形面积。也就是说点的形状和标称面积本来就不一致——这是刻意的保守处理，别去"修正"它。

**做过的检验（你可以复跑验证）**：`矩形外接面积 / 登记面积 > 1.5` 基本可以判定这个框画大了。实测命中过：原图文信息楼 3.23 倍、大食堂 1.87 倍、浴池 2.64 倍。这条检查留作自检，**不许**用它去自动裁剪轮廓（那等于编数据）。

### 5.2 10 组待定位：只登记，不补坐标

**运行时事实**（实测，不是估计）：
- 现有全流程（groups → build_bundle_v2 → add_service_points → viz_25d）在你机器上是**秒级**完成的。
- 浏览器端重算 Dijkstra 也没问题：1100 条边规模下，用"排序数组当优先队列"单次约 2 ms（Node v24 实测）。所以**可以不做后端**。

**为什么不做后端**：算好的结果以 JSON 存下来，前端读 JSON 直接渲染；用户改参数时的重算在浏览器里做，毫秒级。这样能断网演示、零部署、单文件交付。

**为什么不用 Three.js / D3**：这个项目要的是**等轴测 2.5D**（不是透视 3D）+ 有限交互。SVG 手写投影 60 行就够；引 Three.js 意味着构建工具链、着色器调试、坐标系再转一遍——**复杂度收益比很差**（评估过：成本 3~5 倍，答辩友好度反而下降）。如果时间充裕想加分，可以额外做一个 Three.js 版本做对比展示，**主版本保持单文件**。

**坐标转换（必做）**：高德底图是 GCJ-02，你的数据是 WGS-84，实测偏移 **东 511 m / 北 137 m**（合成 529 m）。换算流程：

- 全程计算用 **WGS-84** 局部切平面投米：`m_per_deg_lat = 111320.0`、`m_per_deg_lon = 111320.0 × cos(radians(39.9111)) = 85386.989`；
- **只在出图那一刻**做 `WGS84 → GCJ02`，不要在任何中间量上转；
- 反过来读高德坐标（如量测读点）则要在入口做 `GCJ02 → WGS84`。

直接抄这段（`03_实施方案/技术栈与架构说明.md` §4.2 有完整版）：

```python
A  = 6378245.0
EE = 0.00669342162296594323

def wgs2gcj(lat, lon):
    dlat = _tlat(lon - 105.0, lat - 35.0)
    dlon = _tlon(lon - 105.0, lat - 35.0)
    rad  = radians(lat)
    magic = 1 - EE * sin(rad) ** 2
    slat = sqrt(magic)
    dlat = (dlat * 180.0) / ((A * (1 - EE)) / (magic * slat) * pi)
    dlon = (dlon * 180.0) / (A / slat * cos(rad) * pi)
    return lat + dlat, lon + dlon
```

> `_tlat` / `_tlon` 是两个固定多项式，去 `03_实施方案/技术栈与架构说明.md` §4.2 抄，别自己推。

N = 2**Z * 256
