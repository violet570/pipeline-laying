## P1 · 路网图 + Dijkstra

**目标**：把 `roads` 变成一张可计算的路网图，并把建筑接入到图上，得到任意两点间的**沿路网**最短距离。

**输入**：`bundle.roads`（153 条 way，每条 `{hw, name, pts:[[lon,lat],...]}`）

**做什么**
1. `src/graph.py`
   - `build_graph(roads)` → 邻接表。节点用 `coord_reg[(round(lat,7), round(lon,7))]` **全局去重**（`viz_25d`/`build_bundle_v2` 都是这个键）
   - 边：`{'a','b','len','w','hw'}`，`w = len × 类型系数`（系数表见主文档 §3.5.1，**并且读到那一节关于"代码表 vs 规范表"的口径说明**）
   - 类型过滤不是你的活：`steps` / `construction` 在 bundle 里已经剔掉了，`roads` 就是 153 条
   - `insert_target(g, lat, lon, max_dist=250.0)`：
     ```
     (d, eid, t, qx, qy) = 线性扫描全部边求最近点
     if d > max_dist: return (None, d)
     if t < 1e-4:     return (e['a'], d)      # ★不动图
     if t > 1-1e-4:   return (e['b'], d)      # ★不动图
     # 真正分裂：删原边 + 加两段 + 加新节点
     ```
2. `dijkstra(g, src)` → `(dist, prev)`，`heapq` 二叉堆，`prev[v]` 存**边 id**
3. `path_edges(prev, target)` → 边序列，回溯时 `t = e['a'] if e['b'] == t else e['a']`
4. **连通性预检**：插入任何外部点之前，先 BFS 求连通分量，从**最大分量**里找最近顶点（原始路网是 `components 2, sizes [927, 34]`，那 34 个节点是断头路，接上去就是死路）

**验收命令 / 检查点**
```powershell
python out/p1_check.py
```
必须打印并断言：
```
ways=153  raw_segments=1077
nodes after merge = 961   edges = 1077
components = 2  sizes = [927, 34]  (原始路网，未插点)
after insert 46 pts: nodes = 1035  edges = 1151
UNREACH targets = 0
D01 -> T16 沿路网距离 = <几百米~2km 量级，不是上万>
D01 -> T16 路径边数 = <合理值>
```

**常见错误（对号入座）**
| 现象 | 原因 |
|---|---|
| 长度上千万米 | 经纬度顺序反了，或没投米直接用度 |
| `UNREACH` 大量出现 / 主分量只剩 8 个节点 | 节点没全局去重（按 way 局部建点），图碎了 |
| 边数越插越少 | `insert_target` 端点分支里错误地删了边 |
| 节点数 1003 / 边数 1119 | 插入顺序或端点分支实现与官方略有差异，**允许 ±1，但 MST 必须能算出来** |
| 接到一段孤立的 34 节点小路上 | 没先取最大连通分量 |

**通过标准**：`UNREACH == 0`，节点/边规模在 `1035±1 / 1151±1`，两栋楼的路径长度量级合理。

**预计工作量**：2 h

## P2 · MST + 管径 + 造价

**目标**：从路网图算出管网骨架、每段流量与管径、总造价。**这一阶段的数字必须和 `stats` 完全对上，否则后面所有阶段都建立在错误基础上。**

**输入**：P1 的图 + `bundle.buildings[]`（45 个目标的 `demand` 已算好，直接用）+ `bundle.source_node`

**做什么**
1. `src/mst.py`
   - 以 `[source_node] + [45 个目标 nid]` 为点集（46 点）
   - 每个点跑一次 Dijkstra 建距离表 `D`（46 × 46）
   - Kruskal：`E = C(45,2) = 990` 条目标对（源点只做根，不必两两算），并查集路径压缩，得 **44 条或 45 条边**（见下方口径说明）
2. `src/demand.py`
   - 流量公式（已实测等价，**别重复乘 Kh**）：
     ```
     q_ls = flow_Lpd / (PEAK_HOURS * 3600),  PEAK_HOURS = 24 / Kh = 9.6
     等价写法：q_ls = flow_Lpd * Kh / 86400
     ```
   - 树形 DP：BFS 定 `depth/par/order` → `reversed(order)` 累加 `sub` → **沿 `path_edges` 把流量叠加到路径并集的每条边上**（这是本阶段最容易写错的地方，见主文档 §3.5.4）
   - `pick_dn(q_ls)`：`d_mm = √(4·(q_ls/1000)/(π·v))·1000`，升序取首个 `≥ d_mm`。注意：`q_ls = 199.29` 时 `d_mm = 503.7 mm`，**超过 DN500 → 按"取最大档"处理成 DN500**，这就是 `main_dn = 500` 的由来
   - 造价 = `Σ length × DN_COST[dn]`（用**真实米 `length`**，不是带系数的 `w`）

**验收命令 / 检查点**

| 指标 | 应得值 | 容许误差 | 怎么测 |
|---|---|---|---|
| MST 加权总长 | **8115.9 m** | ±0.1 m | 对 Kruskal 结果求和 |
| 树边条数 | **45** | 必须相等 | `len(mst)`；注意口径：含源点的生成树是 46 个点 → **45 条边**，`tree_edges` 也是 45 条 |
| 管道段数 | **220** | 必须相等 | 路径并集的边数 |
| 管道实长 | **7237.2 m** | ±1 m | `Σ length`；若得到 ≈2400 m，说明 `path_edges` 写错 |
| 总用水量 | **6887.4 m³/d** | ±0.1 | `stats.total_demand_m3d` |
| 设计流量 | **199.29 L/s** | ±0.1 | `q_ls` 最大值 |
| 主干管径 | **DN500** | 必须相等 | `max(dn)` |
| 管径档数 | **13 档，无 DN350** | 必须相等 | `sorted(set(dn))` |
| 造价 | **4682809 元** | ±500 元 | `Σ length × DN_COST[dn]` |
| 最大树深 | **19** | 必须相等 | `max(depth)` |
| 分支点数 | **12** | 必须相等 | **按 `pipes` 端点坐标度算**（`deg[tuple(p['a'])]`），按 `tree_edges` 算是 9，口径不同 |
| 直线 MST 对照 | **5632.2 m** | ±1 m | 质心间 haversine + Kruskal |
| 星形对照 | **40960.8 m** | ±1 m | `Σ D[src][t]` |

**对不上时的排查顺序**（照这个顺序查，别乱改公式）
1. `floor_area` 有没有乘层数？`demand` 有没有乘用水指标？（单点手算 D01：2917.7 × 6 = 17506.0，× 12 = 210071.5 ✔）
2. 用水指标有没有漏掉某个 `cat`？（13 个类别，见主文档 §2.3）
3. `Kh` 是不是乘在日总量上？有没有乘两次？（`Σd/24×Kh/3600` 与 `Σd×Kh/86400` 恒等，别写成第三个式子再乘一次）
4. 管道长度是不是只算了 45 条树边？（应该是路径并集的 220 段）
5. 造价是不是用了带类型系数的 `w`？

**通过标准**：上表 13 行全部通过。**任何一行不过，不要进 P3。**

## P3 · 三档规划模式 + 交互状态机

**目标**：实现"都指定 / 只给终点 / 都不给"三档规划，以及用户中途改参数时的状态流转。

**输入**：P1 的图 + P2 的求解器 + `04_数据/raw/pois.json`（校门）

**做什么**

1. **统一接口**
   ```python
   def plan(source=None, targets=None) -> Plan
   # source : None | ('gate', 'G6') | (lat, lon)
   # targets: None | [building_id, ...]   （None = 全部 45 个）
   ```

2. **判别优先级**（两个状态派生，不要让用户"手动选模式"）
   ```
   hasSource = source is not None        # ★默认假设水源不算 hasSource
   nT        = len(targets or [])
   mode = 'A' if (hasSource and nT >= 1) else \
          'B' if (hasSource is False and nT >= 1) else 'C'
   ```
   两条易错点：① 「默认水源」是 C 模式的**隐含根**，用户没主动选过就不算 `hasSource`，否则 C 模式永远进不去；② 把终点清空要**回到 C**，不是留在 A。

3. **模式 A（都指定）**
   - 起点投影成图节点 `s`（`insert_target`，> 250 m 判失败）
   - 对 `s` 跑一次 Dijkstra
   - `|T| == 1`：直接取 `path_edges`，单条路由
   - `|T| >= 2`：以 `{s} ∪ T` 跑 Kruskal → 树形 DP
   - 复杂度 `O((V+E)logV + N²logN²)`，`N ≤ 46`

4. **模式 B（只给终点，自动选起点）**
   候选集**只有 3 个**，写死（数据依据见主文档 §3.1.2）：

   ```python
   SOURCE_CANDIDATES = [
       ("G7", "西校区7号门（南侧主门，默认假设水源）", 39.9029498, 119.5179052, 11373472154),
       ("G6", "西校区6号门（北侧）",                  39.9166817, 119.5123082, 6396273951),
       ("G5", "西校区5号门（东侧）",                  39.9098098, 119.5300249, 11373472156),
   ]
   ```

   > **三条硬事实**：① 7 号门 **就是** `meta.source`（坐标差 0.0001 m），"南主门"和"7号门"是同一个地方，**不许做成两个候选**；② **没有**东门/西门/北门，别凭空加；③ 东校区 4 号门（node `11373589574`/`11373589575`）**必须排除**。

   算法：对每个候选 `insert_target` → 一次 Dijkstra → `MST_cost([nid] + T_nids, D)` → 取最小；同时算 `star = Σ D[t]` 作对照。

5. **模式 C（都不给）**
   - 根 = `source_node` 所在位置（961）
   - **先读现成结果渲染，同时提供"重算"按钮现场跑一遍做对拍**——两者必须一致，这是最省力的验证

6. **交互状态机**（主文档 §3.1.4 有完整表；这里只列必须实现的三条手势）
   - 点建筑 = **查询**（高亮 + tooltip），**不改模式**
   - `Ctrl/Shift + 点建筑` = 加入终点集 → 若原来在 C，跳到 B
   - 点校门 / 候选表某一行 = 选起点 → 模式升到 A

## P4 · 2.5D 渲染 + 接户四件套

**目标**：把数据画成一张"看得懂"的 2.5D 图，每栋楼都能看出它是怎么接上管网的。

**输入**：`bundle.buildings` / `roads` / `areas` / `pipes` / `service_connections`

**做什么**
1. 投影函数（主文档 §4，直接抄）：
   ```
   THETA = radians(-14.0);  TILT = 0.80
   xr = x·cos - y·sin
   yr = x·sin + y·cos
   screen = (xr, -yr·TILT - z)
   ```
2. **视图拟合**：只拟合「建筑 footprint 顶点 + 水源」，`half = max(宽,高)/2 + 60`；道路按 `|x-cx|<=half and |y-cy|<=half` 裁剪
3. **建筑挤出**：每条边单独一个侧面多边形，**按边中点屏幕 v 降序**绘制（画家算法），顶面最后。明暗 `shade = 0.42 + 0.52·|cos(atan2(y2-y1, x2-x1) - THETA)|`
4. **图层顺序**（照抄）：`道路 → 管道(带 glow) → 建筑 → 接户支管 → tee/立管/出水口 → 指北针比例尺 → 水源`
5. **接户四件套**（读 `service_connections`）：
   - tee：内环 `r=4.2` 填充 `#0a1a22` 描边 `#7fe3ff` 宽 1.6 + 外圈 `r=9` `opacity .10`
   - 支管：`edge_point` → `road_tap`，`#7fe3ff` 宽 1.5 `stroke-dasharray="4,3"`
   - 立管：`edge_point` 处 `z=0 → z=riser_h_m`，`#ffe08a` 宽 2
   - 逐层出水口：`floors[]` 每层一个 `r=1.9` `#ffe08a` 圆点
   > ⚠️ `road_tap` 和 `edge_point` 是**米制局部坐标**，不是经纬度。直接当 `(x, y)` 用。
6. 标注：短名优先（`short`，无名建筑用 `id`），AABB 碰撞避让，位移过大补虚线引线
7. 指北针（用 `iso(0,1,0)-iso(0,0,0)` 求北向）+ 比例尺（100 m）

**答辩要点（提前背熟这三句）**
- **为什么用 MST**："我们要一张连起所有楼的网，不是两点间最短路。MST 保证连通且总长最小。更严格地说，MST 同时是这个问题的下界和可行解，所以最优——但它依赖四条假设：单水源、不考虑管径、不考虑容量、需求点已在路网节点上。"
- **为什么不能直线连**："管道必须沿现有道路。直线 MST 5632.2 m 看着省 27%，但那是把操场和楼都挖开的走法，施工上不可行。沿路网 8115.9 m 才是真实成本。"
- **数据准不准**："建筑轮廓来自 OSM 矢量 + 卫星影像量测，像素读点误差 ±1.5 m 量级。50 栋是 OSM 实测轮廓，11 栋是影像量测的**矩形代理**（图上虚线标出），另有 10 组已知存在但依据不足、**没有补坐标**——这是刻意的，因为之前按 id 抓取时混进过美国北达科他州的乡村道路，教训很痛。水源位置是假设，页面上标了。"

## 卡住了怎么办

| 现象 | 先查 |
|---|---|
| 图上一片空白 | 坐标顺序（`[lon,lat]` vs `[lat,lon]`）、`viewBox` 尺寸、`footprint` 是不是空的 |
| 整张图偏 500 m | 底图没做 GCJ-02 转换 |
| 管道飞到几万米外 | 边的长度用了度而不是米 |
| 大量目标不可达 / 主分量只剩几个节点 | 节点没全局去重；`insert_target` 端点分支删了边 |
| `pipes` 长度算出来 ≈2400 m | `path_edges` 写错，应沿 `prev` 回溯边 id |
| 分支点数算出 9 而不是 12 | 用了 `tree_edges` 口径，应按 `pipes` 端点坐标度 |
| 造价比 4682809 高 | 用了带类型系数的 `w` 当长度 |
| 管径没到 DN500 | `q_ls` 算小了一个量级（漏了 Kh 或单位错） |
| 中文乱码 | `$env:PYTHONIOENCODING='utf-8'` |
| Chrome 截图失败 | 路径含中文，先把 HTML 拷到 `$env:TEMP` |

更多坑见 `07_参考/参考资料与踩坑记录.md`。
