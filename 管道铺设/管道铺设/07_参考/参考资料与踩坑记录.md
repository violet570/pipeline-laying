## 一、规范与标准

| 标准号 | 名称 | 本项目用来做什么 |
|---|---|---|
| GB 50015-2019 | 建筑给水排水设计标准 | 用水定额、时变化系数 Kh、给水系统分区 |
| GB 50013-2018 | 室外给水设计标准 | 室外管网流速、管径选择、水力计算 |
| GB 50788-2012 | 城镇给水排水技术规范 | 管网布置原则 |
| CJJ 92-2016 | 城镇供水管网漏损控制及评定标准 | 漏损率参考（本项目未计入，可作扩展） |

> ⚠ **诚实说明**：这几份标准的原文未能联网核实。`openstd.samr.gov.cn` 明确写着「食品安全、环境保护、工程建设方面的国家标准未纳入本系统」，查「建筑给水排水设计标准」返回 0 条结果。
> 因此本项目的用水指标、Kh、经济流速是**引用标准号 + 工程惯用值**，报告中已标注「以标准原文为准」。正式交作业前建议去图书馆或标准网站核对一遍具体条款。

**经济流速 v = 1.0 m/s** 的取法说明：室外给水管网的经济流速通常在 0.6~1.4 m/s 之间，DN300 以下常取 0.6~1.0，DN300 以上可到 1.0~1.4。本项目统一取 1.0 作为**方案比较的基准**，属于合理简化，不是最优值。

## 三、踩坑记录（按严重程度排序）

### 🔴 P0：OSM way id 污染事故

**现象**：为了让「西区大食堂」「里仁实验楼」等建筑有几何，我用更宽的 bbox 重抓了一次 Overpass，得到 `verify_2026.json`（303 栋，比首次的 103 栋多 201 栋）。从中"确认"了 5 个 way id 对应燕大建筑。

**真相**：这 5 个 id 单独回查后，返回的是**美国北达科他州的乡村道路**：

| way id | 实际坐标 | 实际内容 |
|---|---|---|
| 9676180 | 46.5594, -101.8309 | Grant County, ND，`highway=track` |
| 9676079 | 46.3404, -101.9128 | "72nd Avenue Southwest" |
| 9680716 | 46.6087, -102.5825 | Hettinger County, ND |
| 9473738 | — | 不存在（`missing`） |
| 9473739 | — | 不存在（`missing`） |

两个互相独立的镜像（法国站 + mail.ru 站）返回完全一致，排除单点故障。

**教训**：
1. 批量抓取后必须**按 id 回查 + 地理范围断言**；
2. **不能只看"坐标落在校园框内"就认为 id 正确**——那次抓取的 bbox 逻辑本身有问题；
3. 交叉核对救了一命：`verify_2026` 与首次 `buildings.json` 重叠的 102 个 id，名称 **100% 一致**，证明首次抓取是干净的，污染只在补抓的 201 条里。

**留下的资产**：`scripts/validate_ids.js` + `data/derived/id_validation.json`（193 有效 / 3 境外 / 5 不存在）。

### 🔴 P0：坐标系不转换，整张图偏 500 m

**现象**：把 OSM（WGS-84）的建筑轮廓直接画在高德（GCJ-02）卫星底图上，整体偏移。

**实测偏移**：西校区中心 WGS84 (119.5172, 39.9111) → GCJ-02 (119.523188, 39.912339)，即**东偏 511 m、北偏 137 m**，合成 529 m。

**修法**：计算一律用 WGS-84，只在叠高德底图前调 `wgs2gcj()`。代码见 `03_实施方案/技术栈与架构说明.md §4.2`。

### 🟠 P1：路网图碎裂，只有 7 个目标可达

**现象**：建图后 `.graph components` 显示大量孤立分量，Dijkstra 报 `UNREACH 29`，水源所在连通分量只有 8 个节点。

**根因**：最初按每条 way 的**局部坐标**建节点，导致不同 way 的共享顶点被当成了两个不同节点，图根本不连通。

**修法**：建一个全局坐标注册表 `coord_reg[(round(lat,7), round(lon,7))]`，所有 way 的顶点都通过它取 node id。

---

### 🟠 P1：插入接户点时把边删没了

**现象**：`insert_target()` 逐级调用后，图逐渐断开。

**根因**：原实现无论是否真的分裂了边，最后都执行 `edges.pop(eid)`。当投影点落在边的端点附近（`t < 1e-4` 或 `t > 1-1e-4`）时会直接复用端点，**却仍然把边删掉了**。

**修法**：

```python
if t < 1e-4:   return e['a'], d      # 端点复用，不做任何图修改
if t > 1-1e-4: return e['b'], d
# 只有真正的中点分裂才：
edges.pop(eid); adj[e['a']].remove(eid); adj[e['b']].remove(eid)
nid = add_node(...); add_edge(e['a'], nid); add_edge(nid, e['b'])
```

### 🟠 P1：连接手描支路时接到了孤立小路上

**现象**：补描广场环路后，仍有 5 栋楼不可达。

**根因**：`connect_plaza_ring.py` 最初接"最近 OSM 顶点"，结果接到了一个只有 34 个节点的孤立 `path` 岛上（OSM 在这一带有一条断头小路）。

**修法**：**先从路网切出最大连通分量，只在主分量里找最近顶点**。

```python
comp = {}   # 连通分量标号
# BFS 给每个节点打标
sizes = collections.Counter(comp.values())
main_c = max(sizes, key=sizes.get)
main_nodes = [coords[n] for n in adj if comp[n] == main_c]
```

结果：`components 2, sizes [885, 34]`，接主分量距离分别是 67.6 / 106.1 / 145.5 / 224.7 m。

### 🟠 P1：管道"穿楼"

**现象**：2.5D 图上管道从建筑中间穿过去。

**根因**：11 个影像量测条目的 footprint 是 **bbox 矩形代理**，其中「图文信息楼」是 145×134 m 的框（矩形面积 19,391 m²，而登记面积只有 6,000 m²，**3.23 倍**），把旁边的路和停车场都框进去了。

**量化**：188 段管道中有 24 段落在该框内，另外「大食堂」(1.87×)、「浴池」(2.64×)、「音乐馆」也有同类问题，合计约 1,654 m。

**处理**：
1. 收紧过大的 bbox（按像素网格重新量测）；
2. 无法收紧的，在 2.5D 图上让管道在建筑处"下沉"，表示埋地敷设；
3. **在报告中如实标注这是 bbox 代理的局限性**。

> 检查比例的方法：`矩形面积 / 登记面积`。比值 > 1.5 的基本都是框太大。

### 🟡 P2：自动分割建筑轮廓失败

**尝试**：想用亮度阈值（`lum < 132`）做连通域分割，从卫星图上自动提取屋顶轮廓。

**失败原因**：屋顶亮度不均 + 有阴影，左右相邻的两栋被并成一栋；扫了 95~132 共 8 档阈值都分不开。

**结论**：**人工在像素网格上读点反而更稳**。流程见 `03_实施方案/技术栈与架构说明.md §5`。

### 🟡 P2：经纬网目视估读偏差 20~40 m

**现象**：早期用经纬网（0.0002° ≈ 22 m 网格）目视估读建筑位置，反复修正多轮仍有 20~40 m 偏差。

**修法**：改用**像素网格读点**——`measure_grid.py` 打印 `ox/oy`，人工读像素坐标，再用 `px2ll.py` 反解，精度可达 **±1.5 m**。

### 🟡 P2：图片路径含中文导致 Chrome 截图失败

**现象**：`--screenshot` 报 `net::ERR_FILE_NOT_FOUND`。

**根因**：路径含中文字符/重音符号时，`file://` URI 的 NFD 编码与 Chrome 不匹配。

**修法**：先把 HTML 拷到 `%TEMP%`，再用 `file:///$($env:TEMP -replace '\\','/')/x.htm` 引用。

---

### 🟡 P2：Windows 控制台中文乱码

**修法**：跑 python 前设 `$env:PYTHONIOENCODING='utf-8'`。文件本身是 UTF-8，只是控制台输出乱码。

| 坑 | 现象 | 修法 |
|---|---|---|
| pwsh 不支持 heredoc | `python - <<'PY'` 解析失败 | 多行脚本写成 `.py` 文件 |

## 五、可选的扩展方向（加分项）

| 方向 | 算法 | 难度 |
|---|---|---|
| 多水源（森林而非单树） | 加虚拟超级源点连各水源，跑一次 MST 即得最小生成森林 | 低 |
| 度约束 / 容量约束 MST | 超出经典 MST 范畴，可用启发式或改造成分配问题 | 中 |
| 分期建设 | 树形背包 DP：在预算约束下选子树优先建 | 中 |
| 可靠性（冗余环） | 在原 MST 上补 k 条边形成环，提升单点故障容忍度 | 中 |
| 多方案对拍 | 实现 Prim 与 Kruskal 互验，或对 MST 结果做 2-opt 局部改进 | 低 |

> 其中**多水源**最值得做：真实校园确实有多个接入点（南门、北门），且只需 20 行代码（加超级源点），但故事性很强——从"一棵树"变成"一片森林"。
