# 07_参考/代码原样/ 说明

> 注：本目录是 2026-10-29 的“代码原样”存档，文中 8,163.4 m / 481.8 万元等数字是当时的基准；2026-11-01 环道重描后的现行数字见 `00_README.md`。

本目录收录 **5 个核心脚本的逐字节副本**，作为「参考实现」留档：即使 `06_代码/` 里有人误改或重排，也能从这里取回算法原貌。

## 这 5 个文件是什么

| 文件 | 在流水线中的角色 | 为什么值得单独留一份 |
|---|---|---|
| `groups.py` | **建筑注册表真源**：71 组 / 78 单体的楼名、类别、层数、面积、OSM way id、影像量测 bbox | 全项目的"事实底座"，所有下游数字都由它派生。改楼名只改这里 |
| `build_bundle_v2.py` | **正式方案求解器**：建路网图 → 对 45 个供水目标跑 Kruskal MST → 树形 DP 定管径 → 出 `pipeline_bundle.json` / `pipes_v2.geojson` / `targets_v2.csv` | 当前基准方案（MST 8,163.4 m、造价 481.8 万元）的**唯一**来源，口径必须可追溯 |
| `add_service_points.py` | **接户点层**：每栋楼的路边 tee、接户支管长度、立管高度、逐层出水口径 → `pipeline_bundle_conn.json` | 用户明确要求"不能只在主路上画一笔"，这一层是需求的原点 |
| `merge_plaza_roads.py` | **补环入网**：把用户手描的 5 条广场道路以 `source=user_trace` 追加进 `roads_with_plaza.json` | 记录了"OSM 缺环 → 用户补描 → 进路网"这条关键链路 |
| `viz_25d.py` | **2.5D 视图**：等轴测投影 + 建筑挤出 + 画家算法 + 按管径着色 → `viz_25d.html` | 成品展示页的渲染核心 |

## 与 `06_代码/` 的区别

- **`06_代码/` 是可直接运行的全集**（72 个 `.py` / `.js` + `README_脚本说明.md`，约 352 KB）：抓数、清洗、量测、算法、出图一应俱全，按 README 的「最短可复现路径」可从头跑通。
- **`07_参考/代码原样/` 只是其中 5 个的留档副本**（约 86 KB）：不追求可运行，只追求**内容不被篡改**。这里没有 `README`、没有依赖关系，单独复制出去跑不起来——要跑请用 `06_代码/`。

## 一致性核验

这 5 个副本与 `06_代码/` 中的同名文件 **SHA-256 完全一致**（2026-10-29 校验）。若日后两者出现差异，以 `06_代码/` 为准并重新同步此处。
