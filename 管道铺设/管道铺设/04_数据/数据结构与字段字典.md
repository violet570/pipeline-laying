## 1. 主数据：`pipeline_bundle_conn.json`

这是前端的**唯一数据源**。结构如下：

```
{
  "meta": {...},
  "buildings": [...],        // 61 个建筑群（有几何的）
  "dorms": [...],            // 13 个学生公寓组团
  "source_node": 961,        // 水源在图中的节点号
  "roads": [...],            // 153 条道路折线
  "areas": [...],            // 38 个面状要素
  "pipes": [...],            // 188 段管道
  "tree_edges": [...],       // 45 条 MST 树边
  "stats": {...},
  "service_connections": [...]  // 61 个接户点
}
```

### 1.1 `meta`

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `title` | string | 燕山大学西校区… | 方案标题 |
| `generated` | string | `2026-10-29 18:14` | 生成时间 |
| `crs` | string | `WGS84` | **全部坐标的坐标系** |
| `origin` | [lat, lon] | `[39.9111, 119.5172]` | 局部米制坐标原点（校园中心） |
| `m_per_deg_lat` | float | `111320.0` | 纬度方向 1° 对应米数 |
| `m_per_deg_lon` | float | `85386.989` | 经度方向 1° 对应米数（已乘 cos 纬度） |
| `osm_timestamp` | string | `2026-08-10T00:10:23Z` | OSM 数据快照时间 |
| `registry` | string | `scripts/groups.py` | 建筑名录的真源 |
| `source` | object | `{name, lat, lon}` | 水源点（**假设值**，必须标注） |
| `assumptions` | string[] | 7 条 | 建模假设，页面上要能展开看到 |

**局部米制坐标换算式**（前端用）：

```js
function toMeters(lat, lon) {
  return [
    (lon - meta.origin[1]) * meta.m_per_deg_lon,   // x，向东为正
    (lat - meta.origin[0]) * meta.m_per_deg_lat    // y，向北为正
  ];
}
```

### 1.2 `buildings[]` — 建筑群

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `id` | string | `D01` | 注册表主键 |
| `name` | string | `1组团公寓(1-A/1-B)` | 全名 |
| `short` | string | `1组团` | 图上短名（标签用） |
| `cat` | string | `dorm` | 类别，见 §1.2.1 |
| `group` | string | `D01` | 组团键（同 id） |
| `levels` | int | `6` | 层数 |
| `height` | float | `19.2` | 建筑高度 m（= levels × 3.2） |
| `area` | float | `2917.7` | 基底面积 m²（多栋组团 = 各栋之和） |
| `floor_area` | float | `17506.0` | 建筑面积 m²（= area × levels） |
| `demand` | float | `210071.5` | 日用水量 L/d（非供水目标为 0） |
| `lat` / `lon` | float | `39.90336` / `119.516592` | 主楼轮廓顶点平均（接户/MST 用，**不是组团质心**，见下） |
| `centroid` | [lon,lat] | `[119.5166, 39.9034]` | **面积加权几何质心**（2026-11-05 新增；多栋组团按各栋面积加权，仅作几何参考，不参与 MST） |
| `footprint` | [[lon,lat],…] | 11 点 | **主楼多边形顶点，注意是 [经度, 纬度]** |
| `parts` | [[[lon,lat],…],…] | 2 个多边形 | **全部栋的轮廓**（2026-11-01 新增）；单栋组 == `[footprint]`，12/13 组团各 4 个 |
| `src` | string | `OSM` \| `measured` | 几何来源 |
| `verified` | bool | `true` | 是否经 OSM 或其他权威源确认 |

> ⚠ **坐标顺序陷阱**：`buildings[].footprint` / `parts`、`roads[].pts`、`pipes[].a/b`、`areas[].pts` 全部是 **`[lon, lat]`**；
> 但 `buildings[].lat/lon` 是分开的两个字段，`meta.origin` 是 **`[lat, lon]`**。混用会画出镜像图。
>
> **多栋组团**：`footprint` 只保留面积最大的一栋（兼容旧版前端与接户计算），`parts` 保留全部 78 个单体轮廓（67 OSM + 11 量测）。
> `lat/lon` 是主楼轮廓的顶点平均，用于 MST 的“组团接入点”；不是几何质心，凹多边形时可能落在轮廓外（T05、T14 已如此，属已知边界）。
> `centroid` 是按 `parts` 面积加权的几何质心（T05/T14 的质心已回到楼体内），页面标签用它，MST 仍用 `lat/lon`。
> 2.5D 图已按 `parts` 绘制全部栋。

### 1.4 `pipes[]` — 管道段

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `a` | [lon,lat] | `[119.517875, 39.904135]` | 起点 |
| `b` | [lon,lat] | `[119.517905, 39.90295]` | 终点 |
| `length` | float | `131.94` | 长度 m |
| `flow` | float | `6933740.79` | 该段输送水量 L/d（沿管段累加，已修重复计数；最大 == 总需水） |
| `q_ls` | float | `200.6291` | 设计流量 L/s（含 Kh） |
| `dn` | int | `500` | 公称直径 mm |
| `order` | int | `1` | 铺设层级（从水源向外，= 树深），用于动画时序 |

**管径档位**（14 档）：DN32 / 40 / 50 / 65 / 80 / 100 / 125 / 150 / 200 / 250 / 300 / 350 / 400 / 500

**管径计算公式**：

```
A = Q / v                     # v = 1.0 m/s 经济流速
d = sqrt(4A / π)              # 理论直径 m
DN = 向上取标准档位
```

## 2. 建筑注册表：`groups.py`

**这是全项目建筑名录的唯一真源**。前端不直接读它，但任何新增/改名都必须改这里，然后重跑构建脚本。

```python
dict(
    key='D01',                          # 唯一键
    name='1组团公寓(1-A/1-B)',           # 全名
    short='1组团',                       # 图上短名
    cat='dorm',                          # 类别
    ways=[696195035, 696195036],         # OSM way id 列表（影像量测条目为空）
    levels=6,
    levels_src='official:6层',           # 层数来源，必须写
    verified=True,                       # 是否已确认
    evidence='OSM...',                   # 依据说明
    measured=dict(...)                   # 仅影像量测条目有这个字段
)
```

`measured` 结构：

```python
measured=dict(
    key='canteen-west',
    lat=39.905820, lon=119.515000,       # 中心
    bbox=[119.514100, 39.905300, 119.515900, 39.906350],  # [minLon,minLat,maxLon,maxLat]
    area_m2=9600                          # 实测面积（不是矩形面积！）
)
```

**统计**：71 组 / 78 单体，其中 61 组有几何（50 OSM + 11 影像量测），10 组待定位（Y01–Y11）。

`levels_src` 取值：`osm` / `official:6层` / `assumed:XX` / `measured`。**报告中必须能追溯到来源。**

|---|---|---|

> ⚠ **这不是 OSM 原始数据**。环道是从高德 z18 路网图（`amap_west.png`）的白色道路像素逐 1° 提取的，支路为人工描线；坐标系 WGS-84，环道顶点到高德道路像素中位偏差约 1.4 m。
> 页面上必须以不同颜色/线型区分，并在图例中注明「用户标注（补 OSM 缺失）」。
> 图中的三角形区域是**停车场，不是道路**，不要描进去。

### 3.1 环半径修正：66 m → 145 m → 120.3 m（v4）

第一版描线用像素空间固定值 `CX, CY, R = 1665, 300, 72`（72 px ≈ 66 m），圆心落在信息学院北侧。第二版把圆心南移约 60 m 后仍沿用旧圆心量到的 145 m，整圈比真实环道大约 20%（顶点到高德道路中位偏 19 m、最大 33 m），且首尾差 36.35 m 未闭合。

**v4（2026-11-01）**：不再用「圆心 + 半径」，而是直接从高德 z18 路网图（`05_图件/卫星与底图/amap_west.png`）的白色道路像素逐 1° 提取中心线，平滑后按 5° 重采样成 **72 顶点、首尾闭合**，拟合圆心 (39.916367, 119.515633)、等效半径 **120.3 m**（各方向 104~129 m 不等）。脚本：`06_代码/retrace_plaza_ring_v4.py`；对比图：`05_图件/标注成果/ring_v3_v4_compare.jpg`（灰 = 145 m，品红 = v4）。

v4 的支路处理：四条支路的**外端沿用已吸附到 OSM 主网的坐标**，内端重挂到新环最近顶点；支路若穿楼，自动插入绕角点。

三代对比：

| 指标 | v1 r=66 m | v2 正圆 145 m | **v4（120.3 m，现行）** |
|---|---|---|---|
| MST 加权总长 | 7,717.9 m | 8,163.4 m | **8,115.9 m** |
| 管道实长 | 6,936.6 m | 7,301.2 m | **7,237.2 m** |
| 造价 | 469.5 万 | 481.8 万 | **468.3 万（X01 修正后）** |
| 接户支管中位数 | 25.7 m | 28.4 m | **11.0 m** |
| 路网规模 | 1,004 节点 / 1,120 边 | 988 / 1,103 | **1,035 / 1,151** |

## 7. 用水量模型

**日用水量** = 建筑面积 × 分类用水指标

| 类别 | 指标 L/(m²·d) | 来源 |
|---|---|---|
| 学生公寓 `dorm` | 12.0 | 按 6 人间/间的实际用水反推 |
| 食堂餐厅 `canteen` | 40.0 | 餐饮用水强度高 |
| 服务设施 `service` | 8.0 | — |
| 教学楼 `teaching` | 5.0 | — |
| 办公楼 `office` | 6.0 | — |
| 图书馆 `library` | 5.0 | — |
| 体育场馆 `sports` | 3.0 | — |
| 实验楼 `lab` | 6.0 | — |
| 艺术类 `art` | 3.0 | — |
| 学院楼 `college` | 5.0 | — |
| 活动中心 `activity` | 5.0 | — |
| 市政设施 `utility` | 2.0 | （不计入供水目标） |
| 无名附属 `other` | 0（不供水） | **不供水，demand=0** |

**设计流量**：

```
Q_max = Σd_i / 24 × Kh        # Kh = 2.5 时变化系数
      = Σd_i × Kh / (24 × 3600)   # 换算成 L/s
```

> 注意：`Kh/86400` 与 `Kh/(24×3600)` 数值完全相同（因 86400 = 24×3600），两种写法都对。
> 关键理解：**Kh 乘在日总量上**，等价于"全部日用水集中在 h_peak = 24/Kh = 9.6 小时内均匀用完"。

**当前结果**：Σd = 6,887.4 m³/d → Q_max = 199.29 L/s → 主干 DN500。

## 9. 前端使用建议

```js
// 1. 加载
const B = await (await fetch('04_数据/derived/pipeline_bundle_conn.json')).json();

// 2. 建索引（大部分交互都需要）
const byId = new Map(B.buildings.map(b => [b.id, b]));
const svcById = new Map(B.service_connections.map(c => [c.id, c]));
const tapById = new Map(B.service_connections.map(c => [c.id, c.road_tap]));

// 3. 局部米制坐标
const [LAT0, LON0] = B.meta.origin;
const toXY = (lon, lat) => [
  (lon - LON0) * B.meta.m_per_deg_lon,
  (lat - LAT0) * B.meta.m_per_deg_lat
];

// 4. 2.5D 投影（与 viz_25d.py 完全一致的参数）
const THETA = -14 * Math.PI / 180, TILT = 0.80;
function iso(x, y, z) {
  const xr = x * Math.cos(THETA) - y * Math.sin(THETA);
  const yr = x * Math.sin(THETA) + y * Math.cos(THETA);
  return [xr, -yr * TILT - z];
}
```

## 10. 常见错误清单

| 症状 | 原因 | 修法 |
|---|---|---|
| 图整体偏移约 500 m | 拿 WGS-84 坐标直接叠高德底图 | 先 `wgs2gcj()` |
| 图形上下或左右镜像 | 坐标顺序搞混 `[lon,lat]` vs `[lat,lon]` | 见 §1.2 的警告 |
| 管道穿楼 | 量测条目的 bbox 比真实建筑大 | 收紧 bbox，或让管道在此处下沉表示埋地 |
| 中文乱码 | Windows 控制台默认 GBK | `$env:PYTHONIOENCODING='utf-8'` |
| Pillow 保存报 `FileNotFoundError` | 输出路径含不存在的子目录 | 先 `os.makedirs` |
| Chrome 截图 `ERR_FILE_NOT_FOUND` | 路径含中文，file URI 编码不匹配 | 先拷到 `%TEMP%` 再截图 |
| `TypeError: not enough arguments for format string` | `%` 格式化参数个数不匹配 | 数一遍占位符 |
| 图不连通、只有几个目标可达 | 路网按 way 局部建点，共享顶点没合并 | 用全局 `(round(lat,7), round(lon,7))` 做键合并 |
| 极短管段（0 m 或 0.6 m） | 相邻 A/B 栋共用接户点 | 合并同一组团的接户点，或允许 0 长边 |
