## 1 调研方法与数据源对比

### 1.1 试过的数据源与实测结果

| 数据源 | 能否拿到建筑级矢量 | 实测结果 | 结论 |
|---|---|---|---|
| **Overpass API（OSM 数据）** | ✅ 可以 | `overpass.openstreetmap.fr` 从 Node 的 `fetch` 直连可用（需带 `Referer: https://overpass-turbo.eu/`），8 秒拉完 4 个象限 | **主力数据源，采用** |
| **高德卫星瓦片** | —（栅格影像） | `webst01.is.autonavi.com/appmaptile?style=6` 免 key 直连可用，z17/z18 共下载 656 张，失败 0 | **校验底图，采用** |
| **高德路网瓦片** | — | `webrd01.is.autonavi.com` 同样免 key 可用，带中文注记 | 出图对照用 |
| Google 地图 | ❌ 无逐栋 POI | 本环境 Google 全系域名 fetch 全部失败（网络不可达）；间接证据一致：无逐栋公寓标注 | 放弃 |
| 高德/百度/腾讯 POI 接口 | 需 API key | 开放平台全部强制 key，免费额度需注册 | 未采用 |
| 天地图 | 需 key | 返回 418（WAF 拦截） | 放弃 |
| 百度地图网页 | 反爬 | 返回 recaptcha 验证页 | 放弃 |
| BIGEMAP | 付费 | 有燕大西校区专页，但需付费/客户端 | 参考 |

### 1.2 为什么 OSM 是这次的正解

1. **它是矢量的**：每栋建筑是一个多边形，直接给出轮廓、面积，不需要人工描图。
2. **它有名字和层数**：西校区 72 栋里 54 栋有名字，9 栋带 `building:levels`。
3. **它能算出真实距离**：多边形之间的最小距离就是"外墙面到外墙面"的真实净距，这是管道穿越长度的直接依据。
4. **它是开源的**：ODbL 协议，课程作业引用署名即可，无版权风险。

### 1.3 坐标系处理（这是最容易翻车的地方）

| 坐标系 | 谁在用 | 转化关系 |
|---|---|---|
| WGS-84 | OSM、GPS | 基准 |
| **GCJ-02** | 高德、腾讯 | 西校区中心偏移 **东 511 m / 北 137 m**（合 529 m） |
| BD-09 | 百度 | 在 GCJ-02 基础上再偏，合计东 1055 m / 北 839 m |
| CGCS2000 | 天地图 | ≈ WGS-84 |

**关键点**：宿舍区东西跨度只有 576 m，如果不做坐标转换直接把 OSM 轮廓画到高德底图上，整张管网会飞出校园一个楼群的距离。本项目的做法是：**计算全程用 WGS-84（投影到米制平面），只在出图那一刻做 WGS-84→GCJ-02**，转换公式为标准公开实现（`_tlat`/`_tlon` + 克拉索夫斯基椭球参数 A=6378245.0、EE=0.00669342162296594323）。

### 3.2 配准校验（本报告最硬的一块证据）

**方法**：把 OSM 建筑轮廓（WGS-84）先转 GCJ-02，再投影到 Web Mercator 像素坐标，直接画在高德卫星影像上，**不做任何人工微调**。如果坐标系链路正确，红框应该正好压在屋顶边缘上。

**抽检 6 栋**（`docs/fig/fig6_registration_panels.jpg`）：

| 建筑 | 观察 |
|---|---|
| 里仁教学楼（19,553 m²，最长单体） | 轮廓与屋顶边缘完全重合，东侧凹进的连廊缺口逐一对得上 |

| 电气 C 楼 | 轮廓与屋顶对齐 |

## 4 调研结果三：真实距离

### 4.1 两种距离的定义

- **中心距**：两建筑轮廓顶点平均位置之间的直线距离——反映"两栋楼大致隔多远"，用于画图、描述布局。
- **净距（gap）**：两建筑多边形之间的**最小距离**（外墙面到外墙面）——**这是敷设管道真正关心的量**，横穿距离就是它加上路面宽度。

### 4.2 关键量级（用于核对地图比例尺是否合理）

| 量 | 实测值 | 合理性核对 |
|---|---|---|
| 13 个公寓组团东西跨度 | 576 m | 与真实宿舍带宽度吻合 |
| 13 个公寓组团南北跨度 | 738 m | 与真实规模吻合 |
| 建筑群对总数 | **2,016 对** | 64 组两两组合 |
| 净距中位数 | 478.5 m | 跨组团距离 |
| 净距最大 | 1,552.7 m | 校园对角线量级 |
| 净距 < 30 m 的建筑对 | **55 对** | 管道横向穿越成本最低的相邻关系 |
| 单体底面积最大 | 里仁教学楼 19,553 m²（6 层） | 全校最大单体 |

> 距离表里带 `*` 的是 OSM 没有轮廓、用影像量测补入的 14 个单体。它们的净距用 bbox 矩形近似，是**上限（偏保守）**，精度约 ±1.5 m。全部 2,016 对见 `data/derived/distances.csv`，可读版见 `data/derived/distances.md`。

### 4B.2 核查中查出的严重问题：`verify_2026.json` 的 id 污染

第一轮复核时我用更宽的 bbox 重新查了 Overpass，得到 303 栋（比首次的 102 栋多 201 栋），并据此"确认"了 `燕大西校区大食堂 = way 9676180`、`里仁实验楼 = way 9473739` 等等。

**这个结论是错的。** 把那些 id 单独拿去 Overpass 查证时，返回的是**美国北达科他州（North Dakota）的乡村道路**：

```
way 9676180  →  46.559400, -101.830900   tiger:county=Grant, ND   highway=track
way 9676079  →  46.340430, -101.912800   "72nd Avenue Southwest"
way 9680716  →  46.608690, -102.582510   tiger:county=Hettinger, ND
```

两个互相独立的镜像（`overpass.openstreetmap.fr` 数据时间戳 2026-08-10 与 `maps.mail.ru` 2026-10-28）返回完全一致，排除了单点故障。

于是写 `scripts/validate_ids.js` 把 201 个候选 id 逐个按 id 拉取真实几何、检查坐标是否落在西校区范围内，结果：

| 状态 | 数量 | 说明 |
|---|---|---|
| ✅ 有效（坐标在秦皇岛校园内） | **193** | 可放心使用 |
| ❌ 落在境外（北达科他州） | 3 | `9676079`、`9676180`、`9680716` |
| ❌ OSM 中不存在该 way | 5 | `1620606`、`1620651`、`1620652`、`9473738`、`9473739` |

同时核对：`verify_2026.json` 与 `buildings.json` 重叠的 102 个 id，**名称 100% 一致、位置仅 1 处偏移**——说明首次抓取的 `buildings.json` 是干净的，被污染的是第二次补抓的那 201 条记录（它们的 id 与中心点并未真正绑定到同一对象）。

## 6 对管道方案设计的直接影响

### 6.1 节点该怎么选

**按"建筑群"而不是"单栋"选节点。** 理由直接来自距离表：组团内 A/B 栋净距为 0（连体），单栋建模会给同一栋楼接两次管，虚增负载与管长。

推荐节点集：**64 个建筑群**（含 14 个影像量测补入的，后者精度 ±1.5 m，可放心当节点），或按 5 个分区做**两级方案**（干管分区间 + 支管分区内）。若只想做"公寓管道"这个子问题，则是 13 个组团 / 34 栋单体。

### 6.2 管道路径怎么走

净距表给出了**横穿距离的下界**。管道路径 = 净距 + 路面宽度 + 转弯余量。以相邻教学楼为例：三教–四教净距 20.9 m，若中间是一条主干道（约 8~10 m）加两侧绿化，则横向穿越约 21~25 m，与净距接近——说明**净距本身就是很好的路径长度估计**。

但注意：**净距是直线**。真实管道要沿路敷设，所以最终管长必须走"路网最短路"（Dijkstra）而不是直线距离。项目里已有的 `scripts/build_data.py` 就是这个逻辑：把建筑质心投影到最近路段，在路网图上求最短路，再用 Kruskal 求 MST。

### 6.3 分区加压的可行性

5 个分区的规模表（第 2.3 节）显示：教学实验区总建筑面积最大（27.5 万 m²），学生生活区次之（17.7 万 m²）。若做**分区加压**，B 区是主要负荷，A 区是次要负荷，C/D/E 区较小。这与真实校园给水的分区方案方向一致。

## 7 结论与后续建议

### 7.1 结论

1. **不需要 Google 地图。** 西校区建筑群的矢量数据在 OSM 里基本齐全（67 个单体），OSM 缺的 10 个（两个食堂、圆形广场五栋、里仁实验楼、图文信息楼、亚稳材料国家重点实验室、浴池）已用高德影像量测补齐，并全部通过高德影像配准校验。
2. **"真实距离"已经量化。** 2,016 对建筑群的距离全部实测，相邻楼栋 20~40 m 的量级与校园真实尺度吻合，来源可复现。
3. **"真实卫星影像"已经拿到。** 高德 z17/z18 共 656 张瓦片（110 + 546）覆盖全校区，配准抽检 6 栋建筑轮廓在 1~3 像素内吻合。
4. **方案设计可以直接接着做。** 64 个建筑群节点、5 个分区、按行业标准算出的两两距离，都是 MST 与 Dijkstra 的现成输入。

### 7.2 建议

1. **主图用图 8（64 组注册表全景，细线 + 每群一个标签，已按你的两轮口述修正）**，配图 5/5b（全校区建筑 + 路网对照）与证明图（`proof_canteens.jpg`、`proof_plaza_5.jpg`、`proof_lab.jpg`）——这几张一放，评委会相信"这不是随手画的"。
2. **论文里明确边界口径**：西校区行政边界内含 72 栋（OSM 口径）；体育馆/艺术楼在北侧边界外，若纳入需单列；圆形广场五栋、亚稳材料实验室、里仁实验楼是影像量测补入，标注精度 ±1.5 m。
3. **层数标为推断值**，并在论文里说明来源（官方 6 层 / OSM levels / 按建筑类型推断），避免被追问。
4. **待核实的 15 个无名建筑**可以实地绕一圈确认——这是最容易做的加分项，也是唯一还能提升数据完整度的地方。
5. **不要把净距当管长。** 净距是下界，真实管长走 Dijkstra 路网最短路。
